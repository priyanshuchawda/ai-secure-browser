# Safety Guidelines Caching - Fix Implemented

## Issues Fixed

### 1. ❌ Issue: "Proceed with Caution" didn't work second time
**Problem**: When user clicked another video/link after initial navigation, the button worked but guidelines weren't properly generated/displayed again.

**Root Cause**: 
- No caching mechanism - regenerated guidelines every single time
- Slow AI generation (1-3 seconds) made it seem broken
- User would click multiple times thinking it didn't work

**Solution**: 
- Implemented guidelines caching by domain + threat type
- First request: Generate with AI (1-3 seconds)
- Subsequent requests: Instant from cache (<1ms)
- Cache valid for 24 hours

### 2. ✅ Feature: Cache guidelines to save API calls and improve UX
**Implementation**:
- In-memory Map cache structure
- Cache key: `${domain}:${threatType}` (e.g., "bitcine.app:phishing")
- TTL: 24 hours (configurable)
- Shows cache status in modal footer

## Changes Made

### 1. Main Process (`electron/main/index.ts`)

#### Added Cache Structure (Lines 29-37)
```typescript
// Safety guidelines cache (domain:threatType -> guidelines)
const guidelinesCache = new Map<string, { 
    guidelines: any; 
    threatType: string; 
    timestamp: number;
}>();
const GUIDELINES_CACHE_TTL = 24 * 60 * 60 * 1000; // 24 hours
```

#### Updated IPC Handler (Lines 355-428)
```typescript
ipcMain.handle('security:getSafetyGuidelines', async (_event, { url, assessment }) => {
    // Create cache key from domain and threat type
    const domain = new URL(url).hostname;
    const cacheKey = `${domain}:${assessment.threatType}`;
    
    // Check cache first
    const cached = guidelinesCache.get(cacheKey);
    if (cached && (Date.now() - cached.timestamp) < GUIDELINES_CACHE_TTL) {
        console.log('[IPC] ⚡ Using cached guidelines for:', cacheKey);
        return {
            success: true,
            guidelines: cached.guidelines,
            fromCache: true  // ← New field
        };
    }

    // Generate with AI if not cached
    const guidelines = await guidelinesGen.generateGuidelines(assessment, url);
    
    // Cache the generated guidelines
    guidelinesCache.set(cacheKey, {
        guidelines,
        threatType: assessment.threatType,
        timestamp: Date.now()
    });
    
    return {
        success: true,
        guidelines,
        fromCache: false  // ← New field
    };
});
```

## Cache Characteristics

### Cache Key Strategy
**Format**: `${hostname}:${threatType}`

**Examples**:
- `bitcine.app:phishing`
- `malware-site.com:malware`
- `scam-crypto.io:cryptocurrency_scam`

**Why this works**:
- Same domain + same threat = same guidelines needed
- Different URLs on same domain share guidelines
- Different threat types get unique guidelines

### Cache Invalidation
**Time-based**: 24 hours TTL
- Fresh after 24 hours
- Prevents stale guidelines for changing threats
- Balances freshness vs performance

**Session-based**: 
- Cleared on app restart (in-memory)
- No persistent storage (privacy)
- Fresh start each session

### Memory Management
- Map structure: O(1) lookup
- No size limit currently (could add if needed)
- Typical size: ~5-10 KB per cached guideline
- Max realistic usage: ~100 domains = ~500 KB

## Edge Cases Handled

### 1. Different Threat Types on Same Domain
**Scenario**: Domain switches from phishing to malware
```
bitcine.app:phishing → Cached separately
bitcine.app:malware  → Different cache entry
```

### 2. Cache Expiry
**Scenario**: User returns after 24 hours
```
First visit: Generate fresh guidelines
Cache them for 24 hours
After 24 hours: Generate fresh again
```

### 3. App Restart
**Scenario**: User closes and reopens app
```
Cache is in-memory → Cleared on close
First visit after restart: Fresh generation
```

### 4. API Failure with Cache
**Scenario**: AI fails but cache available
```
Try cache first → If available, return immediately
If not cached and AI fails → Fallback guidelines
```

## Future Enhancements

### Possible Improvements
1. **Persistent Cache**: Save to disk for cross-session caching
2. **LRU Eviction**: Limit cache size with least-recently-used eviction
3. **Manual Refresh**: Button to force fresh guidelines generation
4. **Cache Statistics**: Show cache hit rate in dev tools
5. **Configurable TTL**: Let users set cache duration

### Not Implemented (Intentional)
- ❌ Persistent disk cache (privacy - guidelines contain user visit info)
- ❌ Cross-user cache (each user should get their own)
- ❌ Pre-generation (wasteful - most sites never visited)
